# Жёсткие правила omp-lite

Действуют в каждой сессии этого репозитория. Подробности — в `AGENTS.md`, `dev/PROCESS.md`, `dev/DECISIONS.md`. Принципы владельца — в `dev/WORKFLOW-MANIFEST.md`. Рабочая процедура — skill `omp-lite-engineering`.

## Перед работой

- Прочитай `AGENTS.md`, `dev/PROCESS.md` и `dev/DECISIONS.md`.
- Сначала ищи штатный способ в документации OMP.
- Проверь `dev/BACKLOG.md` и README затронутого модуля.
- Оцени задачу в SP. Больше двух SP — план и согласие владельца.
- Делай только заказанное. Лишнее не добавляй.

## Код

- Выбирай кратчайшее работающее решение.
- Минимум строк и символов. Простота важнее.
- Удаляй мёртвый код, дубли и обёртки.
- Не добавляй зависимость без согласия владельца.
- Отделяй код, данные и тексты.
- Экстеншн: `src/modules/<name>/index.js`.
- Ресурсы: отдельные JSON или YAML рядом.
- README модуля обязателен.
- Тест: `dev/tests/harness/<name>/`.
- README описывает вход, хуки, установку, выключение.

## Проверка

- Запусти изменённое поведение настоящим входом.
- Запусти тест затронутого модуля.
- Перед `main` запусти все тесты.
- Без вывода нет доказательства.
- Сверь дифф с заказом.

## Доставка

- Ветка на задачу, один коммит.
- Полный прогон, merge в `main`, push.
- Обнови `DECISIONS.md` и README при новом решении.
- Не коммить чужие и лишние правки.

## Общение

- Простой русский, короткие предложения.
- Правило дислексии важнее прочих.

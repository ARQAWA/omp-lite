# Установка надстройки в OMP

Это единственный канонический документ установки надстройки в уже установленный OMP. Он не описывает установку самого OMP или настройку рабочего места разработчика. Для установки не требуется исполнять процесс разработки.

Состав поставки задаёт [install.manifest.json](install.manifest.json). Манифест — единственный список устанавливаемых файлов. Рекурсивный обход `src/`, `dev/` и корня репозитория запрещён.

## Что ставится

- Расширения, навыки и системный промпт из списка `files`.
- Настройки из списка `config`.
- Настройки памяти Mnemopi и локальная модель эмбеддингов из блока `mnemopi`.

`README.md`, `dev/`, тесты, `AGENTS.md` и прочая документация разработки не устанавливаются. Наличие файла в репозитории само по себе не делает его ресурсом OMP: устанавливается только запись манифеста.

**Граница цели.** Всё, что перечислено в манифесте, попадает в `~/.omp/agent`. Ничего вне манифеста установщик не копирует.

**Версия OMP.** Надстройка проверена на `18.18.0`. Расширения цепляются за её хуки и точные тексты. Другая версия останавливает установку.

## 1. Память до изменений

Сначала проверь память. Если локальную модель нельзя поставить, остановись до любых файлов и настроек.

**API отвечает, модель есть:**

```bash
curl -fsS http://127.0.0.1:11434/api/tags | grep -q 'embeddinggemma-2:270m'
```

Команда успешна — переходи к шагу 2.

**API отвечает, модели нет:** поставь только модель.

```bash
ollama pull embeddinggemma-2:270m
```

Нет `ollama` на хосте, но API отвечает: скачай модель через API.

```bash
curl -fsS http://127.0.0.1:11434/api/pull -d '{"name":"embeddinggemma-2:270m"}'
```

**API не отвечает.** Проверь `brew` и Ollama:

```bash
command -v brew
command -v ollama
```

Нет `brew` — установка не выполнена: сообщи, что нужен Ollama `embeddinggemma-2:270m` и API на `127.0.0.1:11434`, и заверши без изменений файлов и настроек. Не подменяй локальную модель внешним API и не выдумывай пакетный менеджер.

Есть `brew`:

```bash
brew install ollama
brew services start ollama
ollama pull embeddinggemma-2:270m
```

Есть Ollama, но нет `brew`: запусти `ollama serve` по инструкции установленного Ollama, затем `ollama pull embeddinggemma-2:270m`.

**Проверка эмбеддингов:**

```bash
curl -fsS http://127.0.0.1:11434/v1/embeddings \
  -H 'Content-Type: application/json' \
  -d '{"model":"embeddinggemma-2:270m","input":"ping"}'
```

Ответ содержит массив `data` с вектором — память готова. Сеть нужна для скачивания Ollama и модели.

## 2. Перед копированием

1. Прочитай `install.manifest.json` целиком.
2. Убедись, что `omp` установлен, запускается и его версия `18.18.0`.

```bash
omp --version
```

Ожидается `omp/18.18.0`. Вывод другой: остановись и сообщи версию. Ничего не копируй и не меняй настройки. Обновлять OMP не надо.
3. Закрой активные сессии OMP: расширения читаются при старте.
4. Проверь, что рабочее дерево репозитория чистое. Ставь файлы из коммита, а не из чужих незакоммиченных правок.
5. Найди личный конфиг. OMP читает существующий `config.yaml` на месте; иначе используется `config.yml`.

```bash
config=$HOME/.omp/agent/config.yml
if [ -f "$HOME/.omp/agent/config.yaml" ]; then config=$HOME/.omp/agent/config.yaml; fi
if [ -f "$config" ]; then had_config=1; else had_config=0; fi
```

6. Сделай резервную копию конфига и каждого существующего файла, который будет перезаписан. Запомни файлы, которых не было: при откате их нужно удалить, а не восстановить. Конфига нет — он тоже новый: создай его при слиянии и удали при откате.

```bash
stamp=$(date +%Y%m%d-%H%M%S)
backup=$HOME/.omp/backups/install-contract-$stamp
mkdir -p "$backup"
if [ "$had_config" = 1 ]; then cp "$config" "$backup/config"; fi
```

Для каждой записи `files`: если `~/.omp/agent/<to>` уже существует, скопируй его в `$backup/<to>`; если нет, запиши `<to>` в список новых файлов.

Для старой установки проверь `~/.omp/agent/extensions/background-jobs.js`. Если файл есть, выполни `git hash-object --no-filters` с его путём. Известные хеши: `f0e4487cda3162c4d5ca79930352f8343d371d7e`, `ac81efb39457522a961757110f4d12222f5488e9`. Совпал — создай `$backup/extensions`, сохрани туда файл и удали исходный. Иной хеш — остановись, файл мог быть изменён.

## 3. Файлы

Для каждой записи `files` скопируй ровно один файл:

```bash
mkdir -p "$(dirname "$HOME/.omp/agent/<to>")"
cp "<from>" "$HOME/.omp/agent/<to>"
```

**Удаление старой обёртки.** Если есть `~/.omp/agent/extensions/cursor-tools/`, скопируй каталог в `$backup/extensions/cursor-tools`, затем удали `~/.omp/agent/extensions/cursor-tools/`. Каталога нет — ничего не делай.

Правила:

- `<from>` — путь от корня этого репозитория.
- `<to>` — путь от `~/.omp/agent`; выходить за его пределы нельзя.
- Каталог `extensions/codex-web-run/` создаётся как каталог: расширение грузит `index.js` рядом с ресурсами.
- `skills/reviewer/` хранит скилл, его скрипт, промпты и оверлеи рядом.
- Одинаковые имена и структура каталогов обязательны: код читает ресурсы относительно себя.
- Не копируй каталог целиком и не используй `cp -r` по `src/`.

## 4. Настройки

`config` сливается в найденный личный конфиг по правилам записи:

| mode | что делает |
| --- | --- |
| `merge-missing` | добавляет только отсутствующие ключи; существующие значения не меняет |
| `merge` | выставляет ключи из фрагмента; остальные ключи и вложенные значения не трогает |

Порядок: `runtime-config`, затем `base-tools`, затем `compaction-400k`, затем `status-line`, затем `mnemopi`. Более поздний фрагмент уточняет совпавшие ключи.

`mnemopi` выставляет четыре обязательных ключа:

```yaml
memory:
  backend: mnemopi
mnemopi:
  embeddingModel: embeddinggemma-2:270m
  embeddingApiUrl: http://127.0.0.1:11434/v1
  embeddingApiKey: ollama
```

Остальные личные ключи не меняются. Запрещено заменять конфиг целиком.

**Старое сообщение `sed -n`.** `runtime-config` сливается как `merge-missing`; существующий `bashInterceptor` он не перезаписывает. Найди правило `sed -n` и замени его `message` на:

```text
Use the `read` tool with a line range in `path` instead of sed -n.
```

Остальные правила и личные ключи не трогай.

## 5. Проверка

1. Каждый путь `to` из `files` существует в `~/.omp/agent`.
2. Каждый установленный файл совпадает с файлом репозитория байт в байт. Прочитай `install.manifest.json` и пройди записи `files` циклом: в теле цикла `from` и `to` взяты из записи.

```bash
cmp "$from" "$HOME/.omp/agent/$to"
```

Команда молчит — файлы совпадают. Скажи слово — расхождение, установка неполная.

3. В `~/.omp/agent` нет путей из `dev/`, `dev/tests/`, `AGENTS.md`, `INSTALL.md` и README.
4. В личном конфиге выставлены четыре ключа `mnemopi` и отвечает запрос эмбеддингов.
5. Запусти новую сессию OMP. Расширения не печатают ошибок загрузки.
6. Убедись, что тул `files` отвечает, а команда `reuse` и навыки `blindreview`, `highreview`, `reviewer` доступны.
7. Проверь, что работает установленный `SYSTEM.md`. Запусти сессию вне репозитория и спроси, сколько строк максимум в финальном ответе. Наш промпт говорит про 50-70 строк. Промпт OMP по умолчанию такого числа не знает. Свой `SYSTEM.md` или шаблон в проекте главнее установленного: из каталога с `.omp/SYSTEM.md` эта проверка ничего не покажет.
8. Спроси в новой сессии, когда можно звать саб-агентов. Ответ должен разрешать их только по прямой просьбе, `AGENTS.md` или скиллу. Если модель считает, что вправе звать их сама, проверка не прошла. Это проверяет `task-delegation`.
9. Убедись, что `~/.omp/agent/extensions/background-jobs.js` отсутствует.
10. Попроси обычный подсчёт через `eval`.
Должен выбираться `language: "js"` на Bun.
Python остаётся доступен для специальных библиотек.
Прямые `agent()` и `workpool()` блокируются фильтром.
Это не полное удаление функций из OMP.
11. Проверь `omp config get bashInterceptor.enabled`.
На чистой установке ожидается `true`.
Личный существующий ключ сохраняется режимом `merge-missing`.
`sed -n` должен направляться в `read`.
`ls` и `tree` также направляются в `read`.
12. Проверь `read` для `xd://eval/helpers` с диапазоном в `path`: `xd://eval/helpers:1-5`.
Он должен вернуть первые пять строк без `Unknown topic`.
13. Каталога `~/.omp/agent/extensions/cursor-tools/` нет.

## 6. Откат

1. Для каждого файла, у которого была резервная копия, верни её на место.
2. Каждый файл из списка новых удали.
3. Был удалён каталог обёртки — верни его из `$backup/extensions/`. Не было — оставь удалённым.
4. Был личный конфиг — верни его под исходным именем из резервной копии. Не было — удали созданный конфиг.
5. Перезапусти OMP.

Не удаляй соседние файлы и каталоги, которых не было в манифесте.

## Границы

- Установщик не исполняет тесты и не читает `dev/`.
- Установщик не трогает `~/.omp` вне `~/.omp/agent`.
- Установщик не добавляет зависимости проекта и не запускает `npm install`.
- Установщик не меняет `install.manifest.json` во время установки.
- Новый продуктовый файл попадает в поставку только новой записью манифеста.

# Инструкции по разработке репозитория — не промпт харнеса

Перед работой прочитай [dev/PROCESS.md](dev/PROCESS.md), затем README затронутых каталогов. Эти инструкции относятся к разработке репозитория, а не к работе установленного продукта.

Личные принципы владельца: [dev/WORKFLOW-MANIFEST.md](dev/WORKFLOW-MANIFEST.md). Это отдельная запись, не процедура выполнения задач.

## Документация OMP — первый источник

Жёсткие always-on правила сессии: [.omp/RULES.md](.omp/RULES.md).

**Любое изменение OMP начинай с документации OMP.** Сначала ищи штатный способ. Своего кода нет, пока способ документирован. Способа нет? Предложи костыль владельцу и пометь его.

| вопрос | где читать |
| --- | --- |
| поведение, настройки, расширения, хуки | `omp://` — полный список документов |
| команды и флаги | `omp --help`, `omp <command> --help` |
| текущие значения настроек | `cfg://` |
| границы репозитория | этот файл |
| порядок работы | [dev/PROCESS.md](dev/PROCESS.md) |
| установка в OMP | [INSTALL.md](INSTALL.md) |

Правила:

- в задаче и коммите указывай путь документа OMP;
- каждая правка рантайма возвращается в модуль этого репозитория;
- не выдумывай команды, флаги и ключи настроек;
- документация молчит? уточни, не додумывай.

## Канонический контракт границы

- Исходники продукта и его ресурсы находятся только в [src/](src/README.md).
- Процедуры разработки, настройки разработки, материалы агентов, служебные скрипты и все тесты находятся только в [dev/](dev/README.md).
- Во время работы продукт не импортирует и не читает `dev/` и корневые инструкции.
- Служебные скрипты не переиспользуют внутренности продукта. Тесты вправе импортировать проверяемые модули.
- Правила разработки нельзя включать в продуктовые промпты, навыки и профили. [dev/agents/](dev/agents/README.md) предназначен только для материалов агентов-разработчиков.

Модуль располагается в `src/modules/<module-name>/`, его тесты — в `dev/tests/harness/<module-name>/`. Контракты: [модули](src/modules/README.md) и [тесты продукта](dev/tests/harness/README.md).

## Граница установки

Установщик читает [INSTALL.md](INSTALL.md), а не исполняет процесс разработки. Устанавливаемых модулей пока нет: снимки ещё не оформлены в установочный контракт.

Будущий устанавливаемый состав должен быть явным списком продуктовых файлов, определённым отдельным установочным контрактом, без рекурсивного подхвата всего репозитория. `dev/`, тесты, этот документ и прочая документация разработки в него не входят. README и другие описания сами по себе не становятся ресурсами OMP.

Это процедурная защита агентов. Техническая упаковка и проверка состава поставки появятся вместе с реальным установочным контрактом; сейчас они не реализованы.

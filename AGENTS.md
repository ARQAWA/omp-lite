## Исходники OMP — единственный источник правды

**Механику OMP читай только в исходниках установленной версии.** Сначала ищи штатный способ в коде. Своего кода нет, пока штатный способ есть. Способа нет? Предложи костыль владельцу и пометь его.

Папка исходников на машине одна: `~/ai-project/omp-src`. Это git-клон `https://github.com/can1357/oh-my-pi.git` на теге установленной версии. Основной пакет: `packages/coding-agent/src`. Перед чтением выполни блок: он скачает исходники или переключит тег, если версия другая.

```bash
v=v$(omp --version | cut -d/ -f2); d=$HOME/ai-project/omp-src
[ -d "$d" ] || git clone -q --depth 1 --branch "$v" https://github.com/can1357/oh-my-pi.git "$d"
[ "$(git -C "$d" describe --tags)" = "$v" ] || { git -C "$d" fetch -q --depth 1 origin tag "$v" && git -C "$d" checkout -q "$v"; }
```

| вопрос | где читать |
| --- | --- |
| поведение, настройки, расширения, хуки, команды, флаги | исходники: `~/ai-project/omp-src` |
| текущие значения настроек | `cfg://` |
| границы репозитория | этот файл |
| порядок работы | [dev/PROCESS.md](dev/PROCESS.md) |
| установка в OMP | [INSTALL.md](INSTALL.md) |

Правила:

- в задаче и коммите указывай файл исходников OMP и версию;
- проверка механики значит чтение кода, не только тест;
- каждая правка рантайма возвращается в модуль этого репозитория;
- не выдумывай команды, флаги и ключи настроек;
- в коде не нашёл? уточни, не додумывай.

## Канонический контракт границы

- Исходники продукта и его ресурсы находятся только в [src/](src/README.md).
- Процедуры разработки, настройки разработки, материалы агентов, служебные скрипты и все тесты находятся только в [dev/](dev/README.md).
- Во время работы продукт не импортирует и не читает `dev/` и корневые инструкции.
- Служебные скрипты не переиспользуют внутренности продукта. Тесты вправе импортировать проверяемые модули.
- Правила разработки нельзя включать в продуктовые промпты, навыки и профили. [dev/agents/](dev/agents/README.md) предназначен только для материалов агентов-разработчиков.

Модуль располагается в `src/modules/<module-name>/`, его тесты — в `dev/tests/harness/<module-name>/`. Контракты: [модули](src/modules/README.md) и [тесты продукта](dev/tests/harness/README.md).

## Граница установки

Установщик читает [INSTALL.md](INSTALL.md), а не исполняет процесс разработки.

Состав поставки задаёт [install.manifest.json](install.manifest.json): явный список продуктовых файлов и настроек. Рекурсивный подхват всего репозитория запрещён. `dev/`, тесты, этот документ и прочая документация разработки в него не входят. README и другие описания сами по себе не становятся ресурсами OMP.

Новый продуктовый файл попадает в поставку только новой записью манифеста. Установка без записи запрещена.

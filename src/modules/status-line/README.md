# status-line

Настройка родного статуслайна OMP. Кода нет.

Раскладка: слева π, модель, режим, путь, ветка git и PR. Справа счётчики агентов и фоновых задач, метки подписок и компакшенов, кэш и контекст. Левая группа стоит снизу, правая на верхней линии ввода: так раскладывает форма `composer.shape: claude` из `runtime-config`.
Вторая строка статусов снизу выключена: `showHookStatus: false`, иначе метки дублируются.

Лимиты подписок даёт модуль [subscriptions](../subscriptions/README.md). Фоновые задачи показывает встроенный индикатор OMP. В обычном терминале он не считает сабагентов, показанных отдельно, и может выводить график.

`composer.tokenRate: true` показывает живые `tok/s`. Место — строка работы рядом с названием сессии или строка ввода. Отдельного сегмента статуслайна нет: он убран решением D-020.

**Вход:** фрагмент `status-line.yml` из [манифеста](../../../install.manifest.json). По `INSTALL.md` он сливается в `~/.omp/agent/config.yml`; расширение `ompcli` отдаёт его слоем `PI_CONFIG_FILES`, поверх `config.yml`.

**Выключить:** убрать запись из `config` манифеста и ключи фрагмента из `config.yml`. Остальные ключи `statusLine` и `composer` принадлежат `runtime-config`.

**Тесты:** кода нет. Проверка — `omp gallery --surface=segment` и живой запуск.

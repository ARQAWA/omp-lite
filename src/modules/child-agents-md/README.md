# child-agents-md

Расширение OMP. Даёт сабагенту `AGENTS.md`, который основной агент уже получает.

**Зачем:** исполнитель `task` в OMP 18.18.8 жёстко ставит `excludeAgentsMd: true`. Фильтр по имени файла: любой `AGENTS.md` вырезается, `CLAUDE.md` остаётся. Настройки для этого нет.

**Вход OMP:** `omp://extensions.md`. Событие `before_agent_start` срабатывает и у сабагента: проверено пробой. Сабагента отличает `ctx.agent.kind === "sub"`. Фабрики расширений OMP заново привязывает к каждому сабагенту.

**Поведение:**
- у основного агента ничего не меняется;
- запуск с `--no-context-files`: сабагент тоже ничего не получает (флаг виден расширению только в `process.argv`);
- сабагент получает последним блоком `<repo-rules>` с файлами `AGENTS.md`;
- список берёт тот же поиск OMP, что у основного агента: `loadCapability("context-files")`;
- поиск идёт от `cwd` и от дополнительных корней сессии (`getHeader().additionalDirectories`), как у основного агента;
- порядок как у основного агента: дальний от `cwd` файл первым, ближний последним;
- файл, уже стоящий в промпте, второй раз не добавляется.

**Костыль:** `loadCapability` не описан в документации расширений. Подпуть `@oh-my-pi/pi-coding-agent/capability` собран в бинарь OMP, проба его загрузила. Подпуть `system-prompt` в бинаре недоступен: проба упала. Свой обход каталогов не нужен, поиск общий.

**Границы:** импорты `@путь` раскрывает `expandAtImports` OMP, как у основного агента. Защита от дубля смотрит на тег `<file path="...">`, не на текст файла. Блок встаёт после текста роли сабагента.

**Вход:** `~/.omp/agent/extensions/child-agents-md.js` и `child-agents-md.json` рядом с ним.

**Выключить:** удалить оба файла.

**Тест:** `bun test dev/tests/harness/child-agents-md`.

# child-agents-md

Расширение OMP. Патч рантайма: сабагент получает `AGENTS.md` родным путём OMP, как основной агент.

**Зачем:** исполнитель `task` в OMP 18.18.8 жёстко ставит `excludeAgentsMd: true`. Настройки нет. Фильтр один: `withoutAgentsMd()` в `system-prompt.ts`, строка `files.filter(file => path.basename(file.path).toLowerCase() !== "agents.md")`.

**Костыль (помечен, одобрен владельцем):** штатного способа нет. Патч живёт внутри процесса OMP, бинарь и исходники не меняются.

**Как работает:**
- подменяет `Array.prototype.filter`. Вызов узнаётся по двум признакам: массив контекстных файлов (`path` и `content` строки) и текст условия содержит `"agents.md"`. Такой вызов возвращает копию массива целиком. Остальные вызовы идут в родной `filter`;
- подменяет `globalThis.Worker` в главном потоке: каждый поток получает `preload` с этим файлом. От девяти сабагентов разом OMP уводит их в потоки, а поток режет файлы раньше, чем грузит расширения;
- хуков нет. Экспорт по умолчанию пустой.

**Итог:** файлы отдаёт сам OMP. Блок `<repo-rules>`, порядок, снятие дублей, дополнительные корни, `--no-context-files` и снимок родителя родные.

**Пробы 13.11 (OMP 18.18.8):** блок `<repo-rules>` у сабагента и основного агента совпал по длине и хешу. 12 сабагентов разом на `gpt-6-luna:low`, полный набор расширений: 8 в главном потоке, 4 в отдельном, все 12 с родным блоком, все назвали слово из `AGENTS.md`. Без `preload` четверо из потока блок не получали.

**Границы:** патч глобальный, проверка стоит на каждом `filter` процесса; замера скорости нет. Узнавание идёт по тексту функции OMP: после обновления OMP патч может молча перестать работать. Тогда сабагент снова без `AGENTS.md`, остальное цело. Проверка: пункт 16 в `INSTALL.md`.

**Вход:** `~/.omp/agent/extensions/child-agents-md.js`.

**Выключить:** удалить файл.

**Тест:** `bun test dev/tests/harness/child-agents-md`.

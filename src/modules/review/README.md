# review

Приёмка любой работы: код, план, аналитика.
Проверяются только три вида расхождений:

- заказано, но не сделано;
- сделано, но не заказано;
- сделано не так, как заказано.

Не находка: сценарий «а если», просьба добавить неназванное, правда о внешнем мире, способ и стиль, правила репозитория.
Раздутое это `extra`: ревьюер показывает меньший вариант одной строкой.

Модуль: два профиля сабагентов и три скилла.
Код есть только в скилле: сверка полноты для `eval`.

## Вход

`/blindreview` или `/highreview` через `skill-alias`.
Нативно: `/skill:blindreview`, `/skill:highreview`.
Слова владельца после команды называют, что проверять.
Оба скилла ведут в `skill://reviewer/SKILL.md`.
Он скрыт из каталога: `hide: true`.

## Как работает

1. Основной агент сам смотрит свою работу.
   Незаказанное он убирает до сбора.
   Заказанное, но не сделанное он доделывает (D-073).
2. Агент зовёт сабагента `collector` через `task`.
   Он даёт четыре строки: файл сессии, папку работы, начало задачи, что проверять.
   Строки только указывают место.
   Источники сборщик находит сам.
3. Сборщик читает сессию по её записям.
   Живая ветка кончается в листе.
   Лист это `activeLeafId` последней записи, если он есть.
4. Сборщик пишет `facts.md` во временную папку системы: `omp-review-*`.
   Строки: требования `R1`, элементы набора `R4.1`, ограничения `L1`, работа `W1`.
   Действие без файла тоже строка: `W3 action: ...`.
   Заказанный запуск тоже действие: сборка, тесты, ручная проверка (D-075).
   Способ, который владелец назвал для другого дела, не метод: установщик, пользователь, следующий шаг (D-077).
   Одна фраза владельца даёт одну строку.
   Возражение владельца это приказ.
   Цитата хранит слова о месте, времени и условии.
5. `Deferred`: требования, итог которых владелец положил в файл вне ревью.
   `Replies`: строка на каждую реплику владельца, с её строками или `none` и причиной.
   Источник без стабильных строк сборщик сохраняет в `dir/sources/`.
6. Сборщик ставит печать: SHA-256 в файле `seal`, через `eval`.
7. Каждый круг агент зовёт нового сабагента `acceptor`.
8. Ревьюер сверяет печать, потом отвечает по каждой строке.
   Обе стороны: всё заказанное найдено, каждая часть работы называет своё требование.
   Часть без требования это `no requirement`.
   Элемент ограничения это нарушение, только если ни одно честное прочтение слов ограничения его не допускает.
   В сомнении элемент остаётся.
   Ограничение не растягивают на другие части работы.
   Поздние слова владельца, которые разрешают вещь, главнее ограничения (D-071).
   Строка на каждую часть и каждый элемент набора.
   Каждая строка показывает, что сравнено.
   Статуса `not checked` нет.
   Ответ: `CLEAN`, `FINDINGS` одной пачкой или `BROKEN`.
9. Агент проверяет полноту ответа в `eval`.
   Номер каждой строки `facts.md` и `updates.md` должен начинать строку ответа.
   Имя берётся из id агента в ответе вызова: повторное имя получает суффикс `-2` (D-079).
   Неполный ответ не вердикт.
10. Находку агент сначала открывает сам.
    Верна: самая маленькая правка.
    Неверна: одно возражение в `updates.md`.
    Поднята снова: агент чинит.
    Ревьюер назвал `extra` критичную часть: решает владелец.
    Сделанное и необратимое действие, названное `extra`, закрывает одно возражение с этим фактом (D-078).
    Файл вне `Work` после правки: строка `J1 <путь>` в `updates.md`.
11. Новый заказ или смена объёма после печати: сбор заново.
    Другие новые слова владельца идут в `updates.md`.
12. Принято: два `CLEAN` подряд, разные свежие ревьюеры, работа между ними не менялась.
    Предела кругов нет.
    После приёмки агент удаляет папку.
    Сборщик при старте удаляет папки старше суток.

Модель всегда `openai-codex/gpt-6.1-terra:xhigh`.
Сборщик и ревьюер, blind и high одинаково.
Уровень ревьюера основной агент даёт полем `model`.
Запасных моделей нет.

## Границы

У ревьюера нет `write` и `edit`: их нет в шапке профиля.
Ревьюер ничего не запускает.
Внешний мир он не проверяет.
Память не выключена: OMP сам даёт её сабагенту.
Запрет памяти стоит в промптах обоих профилей.
Печать это сигнал, а не замок.
Цитаты сверяет ревьюер по `id` реплики или `file:line`, не скрипт.
Машинной проверки сборщика нет: он работает по инструкции и на доверии.
Ревью запускает только основная сессия.

## Установка и выключение

Состав задан `install.manifest.json`, процедура в `INSTALL.md`.
Профили ставятся в `~/.omp/agent/agents/`, скиллы в `~/.omp/agent/skills/`.
Выключение: удали эти файлы.
Зависимостей нет.

## Проверка

Тест: `bun test dev/tests/harness/review`.
Он гоняет сверку полноты из скилла на маленьких фикстурах.
Он проверяет шапки профилей и скиллов.

Живая проба:

- `/blindreview` на готовой задаче;
- сборщик отвечает `READY <папка>`, в папке `facts.md` и `seal`;
- ревьюер отвечает `CLEAN` или `FINDINGS` первой строкой и строкой на каждый номер;
- правка `facts.md` после печати даёт `BROKEN`;
- приёмка только после двух `CLEAN` подряд.

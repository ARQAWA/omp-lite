# review

Приёмка согласованной работы через скилл OMP.
Проверяются пропуски, ошибки и несогласованные добавления.
Подход одинаков для планов, контекста, аналитики, кода.

## Вход

`/blindreview`, `/highreview` через существующий `skill-alias`.
Нативно: `/skill:blindreview`, `/skill:highreview`.
Скилл собирает полный пакет первичных материалов.
Затем вызывает инструмент `review`.
Уровни сохраняют Terra high и Terra xhigh.
Запасные модели не выбираются.

## Изоляция

`index.js` вызывает штатный `completeSimple()` OMP.
Источник: `omp://extensions.md` и документация пакета:
https://github.com/can1357/oh-my-pi/blob/v18.18.0/packages/ai/README.md

Контекст состоит из роли, стандартов и пакета.
История, память, инструменты и прежние вердикты отсутствуют.
Агентская сессия OMP вообще не создаётся.
Автовставки Mnemopi и autolearn не запускаются.
Настройки памяти основного агента не изменяются.
Учётные данные предоставляет штатный реестр OMP.
Новых устанавливаемых зависимостей нет.
`@oh-my-pi/pi-ai` уже входит в OMP, лицензия MIT.

Это ограничивает доступ проверяющей модели.
Это не защита от подделки пакета исполнителем.
Исполнитель передаёт оригиналы, не заявления о выполнении.
Недостающие обязательные материалы означают BLOCKED.
Ошибка, отмена или обрезанный ответ не означают CLEAN.

Почему не другие штатные входы:
- `task` и `reuse` не изолируют Mnemopi.
- `completion()` выбирает роли, не нынешние уровни моделей.
- CLI сохраняет автоматически добавляемый контекст.
- SDK-сессия также добавляет служебные сообщения.

Последние ограничения описаны в `omp://system-prompt-customization.md`.
Прямой вызов получает только явно собранный контекст.
Он не использует сессионные хуки и автоматические циклы.
Общие лимиты сессии не управляют этим отдельным запросом.
Отмену передаёт сигнал вызова инструмента.

## Стандарты

`skills/reviewer/WORKFLOW.md` содержит переносимые цитаты владельца.
Их первоисточник: `dev/WORKFLOW-MANIFEST.md` этого репозитория.
Это производный ресурс, не второй редактируемый манифест.
Изменения цитат сверяются с первоисточником тестом.
Рабочие процедуры PROCESS туда не переносятся.
Продукт никогда не читает `dev/` во время работы.
Другие проекты получают тот же установленный ресурс.
Свои применимые правила они передают внутри пакета.

Из EGM использованы проверка замечаний и остановка противоречий.
Источник: https://github.com/google/elephant-goldfish-model/tree/main/skills/egm-resolve
Работу ради удовлетворения проверяющего добавлять нельзя.
Рой агентов и архитектурные стадии не переносятся.

## Установка

Состав задан `install.manifest.json`, процедура в `INSTALL.md`.
Расширение: `extensions/review/index.js` с соседними ресурсами.
Внутренняя структура `skills/reviewer/` сохраняется возле расширения.
Пользовательские SKILL.md устанавливаются в обычный каталог навыков.
Устаревшие агентские профили удаляются по INSTALL.md.
Старый путь `skill://reviewer/REVIEWER.md` больше не используется.
Для выключения удали только файлы этого модуля.

## Проверка после применения

`bun test dev/tests/harness/review`.
Модель и OMP заменены управляемыми данными.
Тест проверяет обычный вход зарегистрированного инструмента.
Он не доказывает качество модельных вердиктов.

В новой OMP-сессии вызови `/blindreview` на плане.
Проверь также аналитику, сбор контекста и результат.
Используй случаи из `dev/tests/harness/review/cases.json`.
Передавай `packet` полностью, сравнивай требуемый статус.
Прогони случаи на обоих уровнях ревью.

Отдельно проверь реальный исходящий запрос через `onPayload`.
Этот callback документирован в README пакета pi-ai.
Он должен содержать только роль, стандарты, пакет.
Инструментов и родительского маркера памяти быть не должно.
Следующий вызов не содержит предыдущий пакет или вердикт.
Настройки Mnemopi основного агента остаются прежними.
Проверку выполняй до заявления о живой изоляции.

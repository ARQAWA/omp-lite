# rqw-windows-pack

RQW Windows Pack переносит харнес на Windows VDI без прав администратора. Для OMP 19.0.0.

1. **OMP во вкладке VS Code.** Расширение `arqawa.ompcli` несёт `omp.exe` и ставит харнес само.
2. **Диктовка.** `alt+w` начинает запись, второй `alt+w` ставит текст в конец поля ввода. Работает только во вкладке OMP CLI на Windows.

**До правки запуска прочти [dev/VDI.md](../../../dev/VDI.md): правило запуска и факты о VDI.**

## Файлы

- `vscode/index.js`: весь код расширения VS Code. `vscode/package.json`: три команды и две клавиши.
- `vscode/runtime.json`: закреплённые программы и модель, с размером и SHA-256. Единственное место пинов.
- `vscode/messages.json`: все видимые тексты, английский.
- `voice/index.js`: весь код диктовки, свой.
- `voice/stt.windows.json`: клавиша, микрофон, настройки Soniox, тексты.

В рантайме мест два. `vscode/` это расширение VS Code. `voice/` это расширение OMP в `~/.omp/agent/extensions/pi-voice-stt/`. На VDI второе место заполняет первое: ставится только расширение VS Code.

## Команды и клавиши

Категория `OMP CLI`: `New Tab` (вкладка `OMP N`), `New Terminal Tab` (Git Bash с `omp` в `PATH`, вкладка `OMP terminal N`), `Update`. Вход в провайдеров: обычный `/login`.

Перед командой расширение проверяет Windows x64, Git Bash `C:\Program Files\Git\bin\bash.exe`, `node-pty` внутри VS Code и профиль OMP по умолчанию. Оно ничего из этого не ставит, только называет причину. Активация только регистрирует команды.

Во вкладке расширения Shift+Enter уходит как `ESC[13;2u` (перенос строки), Ctrl+Enter как `ESC[13;5u` (сообщение в очередь). В чужих терминалах клавиши не перехватываются.

## Цепочка запуска

Программу из поставки расширение запускает только так:

```text
node-pty из VS Code
  -> powershell.exe -NoLogo -NoProfile -Command "& 'C:\Program Files\Git\bin\bash.exe' --login -i -c '<команда>'"
     -> Git Bash
        -> программа
```

Каждый аргумент команды стоит в одинарных кавычках, в путях прямые слеши, двойных кавычек нет, секреты идут только через окружение. Так идёт `omp.exe`. `ffmpeg.exe` запускает сам OMP тем же хвостом: PowerShell, Git Bash, программа. Прямой запуск программы из extension host VDI запрещает (`spawn EPERM`). Сам extension host запускает одну программу: `curl.exe` из `System32`.

## Программы и сеть

В VSIX лежат `runtime/omp.exe`, `runtime/ffmpeg.exe` и `runtime/llama/`. Сервер llama.cpp расширение не запускает. Скачивается только модель эмбеддингов, это данные: `globalStorage/model/`, проверка размера и SHA-256 при каждой вкладке. Её никто не читает; модель не скачалась: вкладка открывается, VS Code пишет `OMP CLI could not download <имя>: <причина>`.

Прокси берётся из `http.proxy`; настройка пуста: из окружения VS Code (`HTTPS_PROXY`, `HTTP_PROXY`, `ALL_PROXY`). С прокси всё идёт через `curl.exe` с тремя повторами загрузки, без прокси через `fetch`. `http.proxyStrictSSL: false` добавляет `--insecure` и ставит вкладке `NODE_TLS_REJECT_UNAUTHORIZED=0`; без этой настройки проверка TLS не выключается. Пароль прокси идёт только через окружение.

## Установка харнеса

Харнес ставится при открытии вкладки и командой `Update`, внутри extension host, без программ. Состав задаёт [install.manifest.json](../../../install.manifest.json): `files` копируются в `~/.omp/agent`, пути `remove` удаляются. Абсолютные пути, `..` и ссылки отклоняются. Изменяемый файл сначала уходит в `agentDir/.ompcli-backups/` с журналом; ошибка возвращает прежнее состояние, прерванную установку откатывает следующая.

`config.yml` расширение не читает и не пишет. Фрагменты `config` манифеста идут в OMP слоями через `PI_CONFIG_FILES`: прежние слои владельца, фрагменты по порядку манифеста, слой расширения `globalStorage/memory.yml` с одной настройкой `memory.backend: off`. Памяти на VDI нет. Поздний слой перекрывает ранний, все слои перекрывают `config.yml`.

Перед первой командой окна расширение чистит `globalStorage`. Остаются `model/`, `payload/<версия расширения>/`, `shell-<pid>.sh` живых окон, `memory.yml`, `stt.json`, файл ключа диктовки. Остальное удаляется.

## Update

`Update` берёт `main` из `ARQAWA/omp-lite`, распаковывает названные манифестом файлы в `globalStorage/payload/<версия>/<sha>/` и ставит их тем же установщиком. Указатель `current.json` пишется в одной транзакции с файлами. После успеха прочие ревизии удаляются. Ревизию, которая уже лежит на диске, `Update` ставит заново: потерянный файл возвращается.

- Открыты вкладки OMP: `Close OMP CLI tabs before updating.`
- В `main` другой `runtime.json`, то есть сменились программы: `OMP CLI bootstrap changed. Update OMP CLI in Marketplace.` Ничего не ставится.
- В `main` другой код расширения: харнес ставится, VS Code пишет `A newer OMP CLI is in Marketplace.`
- Блок `__metadata`, который VS Code дописывает в `package.json`, изменением не считается.

**`Update` и обновление расширения делаются при одном открытом окне VS Code без вкладок OMP.** Защиты между окнами нет.

## Диктовка

Плагин включается при двух условиях: система Windows и переменная `OMPCLI_GIT_BASH`, её ставит вкладка. Иначе он ничего не регистрирует: на Mac нет надписи, клавиш, команды и тулов.

1. `alt+w` начинает запись, второй `alt+w` ставит текст в конец поля ввода. `Enter` во время записи сразу отправляет текст. `Esc` отменяет запись и распознавание.
2. Надпись стоит в левом краю верхней рамки поля ввода: `voice alt+w`, при записи мигающая точка и `recording`, потом `transcribing`.
3. Звук пишет `ffmpeg` из поставки: `dshow`, микрофон `audio=Remote Audio`, WAV 16 кГц моно. Запуск цепочкой PowerShell, Git Bash, программа. Остановка: `q` в stdin, через три секунды `taskkill` по дереву процессов.
4. Проверка тишины: файл меньше 4096 байт или пик не выше 3 даёт ошибку, запрос в Soniox не идёт.
5. Распознаёт Soniox, модель `stt-async-v6`. Настройки взяты из прокси `superwhisper-soniox-proxy`: подсказки языков `ru`, `en`, определение языка включено, разделение говорящих выключено, текст контекста про техническую диктовку, опрос раз в 250 мс. Списков слов нет. Файл и заказ в Soniox удаляются после ответа.
6. `/stt doctor` проверяет файл ключа и запуск `ffmpeg` цепочкой.

Ключа нет в репозитории и в поставке. Вкладка пишет `globalStorage/stt.json` из `stt.windows.json` и пути к файлу ключа `%APPDATA%\Code\User\globalStorage\arqawa.ompcli\ad591530-694c-42f1-9f01-f03bee4cca1c.txt`. В файле одна строка: ключ. Плагин читает его при каждой записи; файла нет: ошибка называет путь.

Чего нет: других сервисов, потокового режима, профилей, чистки текста моделью, голосовых команд, расшифровки файлов, тула `transcribe_audio`, предела длины записи, цвета рамки по режиму.

## Выключение

Удалить расширение из VS Code: программы и слои настроек уходят с ним; файлы в `~/.omp/agent` остаются. Диктовка: строка `extension-module:pi-voice-stt` в настройке `disabledExtensions`.

## Механика OMP 19.0.0

Каталог исходников: `packages/coding-agent/src`.

- `config/settings.ts`: слои настроек из `PI_CONFIG_FILES` и `--config`, поздний побеждает.
- `discovery/helpers.ts`, `discoverExtensionModulePaths`: папка `extensions/<имя>/` с `index.js` это одно расширение. `getExtensionNameFromPath`: его имя это папка, `pi-voice-stt`.
- `extensibility/extensions/loader.ts`, `discoverExtensionPaths`: выключение по строке `extension-module:<имя>`.
- `modes/interactive-mode.ts`, `setEditorComponent`: расширение ставит фабрику поля ввода; диктовка оборачивает его `render`.
- `extensibility/extensions/types.ts`, `onTerminalInput`: расширение видит клавиши до поля ввода и может их забрать.
- `packages/tui/src/utils.ts`, `extractSegments`: остаток строки после надписи сохраняет цвета.
- `packages/tui/src/keys.ts`: разбор `ESC[13;2u` и `ESC[13;5u`.

## Известные проблемы

Их решено пока не трогать.

- Хеши программ при старте не сверяются: проверяется только размер `omp.exe`.
- Сервер и модель эмбеддингов занимают место и не используются.
- Слой настроек на VDI перекрывает `modelRoles.default` владельца.
- `PI_CONFIG_DIR` не учитывается. Именованный профиль OMP не поддерживается.
- Второе окно VS Code во время `Update` или первой вкладки после обновления может сломать установку.
- Любая правка `runtime.json` блокирует `Update`, правка адреса модели тоже.
- Заметка о новой версии может выйти зря, когда код в `main` правили без выпуска.
- `/stt doctor` микрофон не проверяет. Клиент VDI без проброса звука даёт пустую запись.
- Вид надписи слева на VDI проверяется только глазами: на Mac плагин выключен.

## Тест и сборка

`bun test dev/tests/harness/rqw-windows-pack`. Тесты идут на Mac и Windows не запускают; проверка VDI за владельцем.

Сборка папки расширения: `bun dev/scripts/rqw-windows-pack/build/index.js`, результат в `dist/ompcli`. Сборщик требует чистого рабочего дерева и программу `cabextract`. Упаковка: `vsce package --target win32-x64`.

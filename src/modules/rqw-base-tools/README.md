# rqw-base-tools

тулинг агента для работы с файлами.

**назначение:**
1. Обычные локальные `grep` и `glob` и `read` непустого локального текста с `offset` или `limit` работают по образцу Cursor. `glob` даёт список по маске от новых файлов к старым, полный счёт и число скрытых из вывода путей; поиск от корня файловой системы запрещён, `limit` положительный. `grep` даёт совпавшие пути (`files_with_matches`) или счёт по файлам (`count`), с `head_limit` и `offset`. Многострочный поиск предупреждает об окне 4 МиБ для файла и каталога, в том числе без совпадений. В режиме `content` по возможности показывает метку и строки для `hashline edit`; в режиме `replace` и без `edit` метки нет. В `read` `offset` — ненулевое целое: положительное от начала, отрицательное от конца; `limit` — положительное число строк. Список каталога и `read` без диапазона идут родному тулу OMP. Пустой файл даже с диапазоном получает родной ответ. Для редких целей `read` принимает только `path`; `grep` и `glob` делегируют редкие цели и родные параметры через `ctx.invokeTool`.
2. Свои описания `bash`, `edit`, `write`. Сторож проверяет родные схемы, описания, настройки и импорты движка.
3. Правка по файлам в режиме `hashline`: независимая секция с неверным или непоказанным якорем может быть пропущена, остальные идут на запись; ошибка формата может отклонить весь патч. При ошибке записи надо проверить результат: часть файлов могла измениться.
4. Метка `[whole file: N lines]` подтверждает полное чтение обычного текста без обрезки. При `?` в `path` метки нет, даже если это часть имени файла.

**вход:** `index.js`, `rqw-base-tools.texts.json`, `rqw-base-tools.reference.json`, `rqw-base-tools.yml`.

**хуки:** `session_start`, `before_provider_request`, `tool_call`, `tool_result`, `tool_execution_end`. Тулы: `grep`, `glob`, `read`.

**установка:** три файла в `~/.omp/agent/extensions/rqw-base-tools/`. `rqw-base-tools.yml` вливается в `config.yml`. записи в `install.manifest.json`.

**настройки:** `rqw-base-tools.yml`, 18 значений. Восемь из них сверяет сторож. `tools.intentTracing: true` сохраняет поле `i` в вызовах тулов и вне интерактивного режима. `grep.contextBefore/After: 3` действует только на родной маршрут; локальный `grep` по Cursor начинает с нуля. Четыре ключа выноса ответа в файл: `tools.artifactHeadBytes`, `tools.artifactTailBytes`, `tools.artifactTailLines`, `tools.artifactMaxBytes`. `find.enabled: "off"`, `astGrep.enabled: false` и `disassembler.backend: none`. Перехват bash: `bashInterceptor.enabled: true` и 9 правил.

**перехват bash:** вместо команд чтения, поиска и вывода списков OMP предлагает `read`, `grep` или `glob`. правка на месте (`sed -i`, `perl -i`, `awk -i inplace`) проходит. свои `patterns` заменяют встроенный список OMP, не дополняют. это предпочтение, не изоляция: перехват не разбирает код интерпретаторов и не блокирует все пайпы.

**выключение:** `extension-module:rqw-base-tools` в `disabledExtensions`. настройки файла убрать из конфига руками.

**тест:** `bun test dev/tests/harness/rqw-base-tools`.

**костыль и границы:** OMP 19.0.0: `packages/agent/src/agent-loop.ts:3152-3257` готовит вызовы в порядке ответа; расширение ждёт завершения предшествующих `bash` перед проверкой локального диапазона. `packages/coding-agent/src/sdk.ts:3998-4005,4049-4075` оставляет родной тул для `ctx.invokeTool`; `tools/read.ts:3334-3345` и `tools/grep.ts:1295-1305,1431-1445` записывают снимок и показанные строки для `edit`. Локальный поиск пользуется `@oh-my-pi/pi-natives`; `grep` регистрирует показанные строки не длиннее 512 байт через родной `grep`. При обрезанной строке в блоке или файле свыше 4 МиБ метки нет; в режиме `hashline` без метки или для правки более длинной строки сначала вызови `read`. Порог 4 МиБ совпадает с пределом сохранённого снимка OMP, но родная метка возможна до 64 МиБ (`crates/edit/src/store.rs:20-26,371-389`). Для отсева используется отдельное хранилище показанных строк и независимая копия на каждую проверку, чтобы проба не помечала непоказанные строки как увиденные; окончательную правку и разрешения проверяет родной `edit`. Режим меток определяет `utils/file-display-mode.ts`. Импорты внутренних классов тулов и `stripOutputNotice` — обход; сторож проверяет схемы и экспорты.

**после обновления OMP:** переснять эталон с живого запроса. проверить числа в текстах.

**правка текста:** изменить JSON и открыть новую сессию.

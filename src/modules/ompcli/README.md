# ompcli — OMP для Windows VDI

**До правки запуска прочти [dev/VDI.md](../../../dev/VDI.md): правило запуска и факты о VDI.**

Расширение VS Code `arqawa.ompcli` ставит харнес omp-lite на Windows VDI и открывает
вкладки OMP без ручной установки. Проверку самой VDI делает владелец.

## Что делает

- `OMP CLI: New Tab` — вкладка OMP N. Цепочка: extension host → PowerShell → Git Bash → `omp.exe`.
- `OMP CLI: New Terminal Tab` — интерактивный Git Bash с комплектным `omp` в `PATH`.
- `OMP CLI: Update` — забирает свежий `main` из `ARQAWA/omp-lite` и применяет харнес.
- Локальная память: `llama-server.exe` с моделью EmbeddingGemma 2 Q8_0 на loopback.

Активация только регистрирует команды. Модель не загружается, OMP не запускается.

## Ресурсы

|файл|назначение|
|---|---|
|`index.js`|весь код расширения VS Code: вкладки, установка харнеса, обновление, память|
|`package.json`|манифест расширения: три команды, Ctrl+Enter и Shift+Enter, `main: ./index.js`|
|`runtime.json`|пины OMP, модели, llama.cpp, CRT и ffmpeg: `url`, `sha256`, `size`, `file`; программы по ним кладёт в VSIX сборщик|
|`messages.json`|видимые сообщения, английский|
|`licenses/`|лицензии OMP, llama.cpp, LLVM OpenMP, модели, Bun и условия MSVC runtime|

`runtime.json` — единственное место пинов. Служебный сборщик находит его через
[install.manifest.json](../../../install.manifest.json), раздел `vscode`.

## Установка

Программ в VSIX три: `runtime/omp.exe` (OMP 18.18.8), `runtime/llama/` с сервером
памяти и `runtime/ffmpeg.exe` для диктовки (сборка LGPL `n8.1.3`, FFmpeg-Builds). `bun.exe` в поставке нет: VDI запрещает сам этот файл (`Permission denied`).

Запуск у всех программ один, как у PCLI: `node-pty` из VS Code -> `powershell.exe` ->
Git Bash `--login -i -c` -> программа. Второго bash и файла-обёртки между ними нет.
Пути в команде идут с прямыми слешами, двойных кавычек в ней нет. Сам extension host
запускает только `curl.exe` из `System32`: им качаются модель и обновление.

**Установка харнеса и распаковка обновления идут внутри extension host, без программ.**
Так устроен и PCLI. Для этого расширению не нужен разбор YAML: `config.yml` владельца
оно не читает и не пишет.

Скачивается только модель, это данные: `globalStorage/model/<файл>`, с проверкой размера
и SHA-256. Загрузка повторяется до трёх раз. Версии до 0.0.4 держали комплект в
`globalStorage/runtime/`: первый запуск переносит оттуда годную модель и удаляет каталог.
Нет программы в каталоге расширения или её размер другой — вкладка не открывается
и называет файл.

Сеть нужна к GitHub, Hugging Face и провайдерам. Прокси берётся из `http.proxy`; настройка
пуста — из окружения VS Code: `HTTPS_PROXY`, затем `HTTP_PROXY`, затем `ALL_PROXY`. С прокси загрузка
идёт через `curl.exe`: `fetch` в extension host прокси не читает.
Явный `http.proxyStrictSSL: false` добавляет `--insecure`.

Харнес ставится по `install.manifest.json`: файлы `~/.omp/agent` копируются.
Файлы из списка `remove` удаляются; опустевший каталог расширения тоже. Откат возвращает их.
Личные настройки, `auth`, `sessions` и `memories` не читаются и не копируются.

Настройки харнеса в `config.yml` не сливаются. Фрагменты из раздела `config` манифеста
идут в OMP слоями через `PI_CONFIG_FILES`.
Порядок: прежние слои владельца, фрагменты по порядку манифеста, overlay памяти окна.
Поздний файл перекрывает ранний, а все слои перекрывают `config.yml`. Поля `to` и `mode`
манифеста расширение не использует: они нужны установке по `INSTALL.md`. Следствие:
настройку из слепка нельзя сменить из самого OMP, пока открыта вкладка расширения.

При старте расширение убирает хвосты прежних версий и упавших запусков: каталог
`globalStorage/runtime`, `extract.js`, `chat-*.sh`, `shell-<pid>.sh` и `runs/<pid>-*`
умерших окон, payload других версий расширения (когда ни одно окно не держит вкладку),
а также `install-*.json`, архивы и `*.tmp` старше суток.

Запись сериализуется именованным каналом `\\.\pipe\arqawa-ompcli-install-<sha256(agentDir)>`.
Внутри одного окна вкладки и `Update` берут канал по очереди: две первые вкладки
открываются вместе. Канал, занятый другим окном, даёт `OMP CLI installation is busy.`
Изменяемые файлы уходят в `agentDir/.ompcli-backups/` с журналом; ошибка возвращает
прежнее состояние. Замена файла, занятого антивирусом, повторяется около секунды. Живые вкладки регистрируются в `globalStorage/leases/<pid>.json`
вместе с ревизией payload. Вкладка, закрытая во время загрузки, записи не оставляет,
даже если загрузка потом упала.

`Update` берёт `main` из `ARQAWA/omp-lite`, кладёт payload в
`globalStorage/payload/<версия расширения>/<sha>/` и ставит его тем же установщиком.
Ревизию, которая уже лежит в хранилище или в самом расширении, `Update` ставит заново:
потерянный файл харнеса возвращается, а первый `Update` после установки расширения тоже
ставит харнес. Если всё на месте, изменений нет.
Указатель `current.json` пишется в одной транзакции с файлами харнеса: сбой любой
записи возвращает файлы, настройки и указатель. Архив качается в файл со своим именем
на каждую попытку: оборванная загрузка не мешает повтору. Каталог ревизии готовится под
тем же lease, что и установка: второе одновременное обновление получает
`OMP CLI installation is busy.` Сначала `Update` откатывает прерванную установку, потом
сверяет указатель. После загрузки откат и сверка повторяются под lease: готовую ревизию
второе обновление не трогает, а прерванную не принимает за готовую.
Новый VSIX нужен, только если изменился `runtime.json`: это пины программ. Тогда `Update` ничего не ставит.
Другие файлы bootstrap изменились? Харнес ставится, а VS Code пишет `A newer OMP CLI is in Marketplace.`
Блок `__metadata`, который VS Code дописывает в установленный `package.json`, изменением не считается.

## Клавиши

Терминал VS Code шлёт на Shift+Enter и Ctrl+Enter обычный Enter. Во вкладке расширения
они уходят в OMP как `ESC[13;2u` и `ESC[13;5u`: Shift+Enter переносит строку,
Ctrl+Enter ставит сообщение в очередь.

## Диктовка

Плагин `pi-voice-stt` ставится с харнесом (модуль `voice-stt`). Вкладка пишет конфиг окна
`globalStorage/stt.json`: это `stt.windows.json` из каталога плагина плюс `provider.apiKeyFile` с путём
`globalStorage/ad591530-694c-42f1-9f01-f03bee4cca1c.txt`. OMP получает `PI_STT_CONFIG` на этот файл и `OMPCLI_GIT_BASH`.
Плагин читает файл ключа при каждой записи: ключ, записанный при открытой вкладке, тоже работает.
`SONIOX_API_KEY` в окружении Windows главнее файла. Ключа нет нигде: `/stt doctor` называет путь файла.

ffmpeg запускает сам OMP, цепочкой PowerShell -> Git Bash -> `ffmpeg.exe`. `ffmpeg.exe` лежит рядом
с `omp.exe`, а этот каталог вкладка ставит в `PATH`.

## Память

Один сервер на окно extension host, свободный порт на `127.0.0.1`, ключ процесса.
Запуск: `--embeddings --pooling mean --ctx-size 8192 --batch-size 8192 --ubatch-size 8192
--parallel 1 --threads 2 --no-webui`. Готовность — `GET /health` до 60 секунд, затем две
пробы `/v1/embeddings` с проверкой 768 измерений. Сервер, который умер сразу после проб,
запущенным не считается.

Сервер не запустился? Вкладка всё равно открывает OMP, но без памяти: overlay окна ставит
`memory.backend: off`. Вкладка и предупреждение VS Code называют причину вместе с
последними строками скрытого терминала сервера. Следующая вкладка пробует сервер снова.

Окно получает свой overlay `globalStorage/runs/<pid>-<uuid>/memory.yml`. Перезапущенный
сервер имеет новый ключ, поэтому следующая вкладка получает новый overlay, даже на том же порту. Вкладка OMP
после профиля Git Bash снимает строчные прокси, возвращает выбранные прокси, включая
`PI_PROXY`, `PATH` и `PI_CONFIG_FILES` и запускает OMP с `--config`. Вкладка терминала
делает то же файлом `globalStorage/shell-<pid>.sh` и оставляет Git Bash открытым. Прежние
overlay остаются первыми в списке.
Пароли прокси идут только через окружение. Постоянные настройки Mac не меняются.

## Выключение

Удалить расширение из VS Code: программы и слои настроек уходят вместе с ним. Файлы в `~/.omp/agent`,
модель в `globalStorage/model` и базы памяти остаются. Отдельной настройки выключения нет.

## Границы

- Windows x64 и Git Bash `C:\Program Files\Git\bin\bash.exe` обязательны; расширение их не ставит.
- `node-pty` берётся из самого VS Code: `node_modules.asar/node-pty`, затем `node_modules/node-pty`.
- Именованный профиль OMP не поддерживается: `OMP CLI requires the default OMP profile.`
- Версия OMP закреплена: 18.18.8. Автообновления OMP нет.
- Проверка VDI, Windows-запуск и скриншоты принадлежат владельцу.

### 2026-11-07 — Простой вариант: Luna с `xhigh` и `priority`, расширение

**Решение:** Поиск делает GPT-6 Luna с усилием `xhigh` и tier `priority`. Поле `service_tier` в `alpha/search` не принимается, поэтому `priority` ставится только на ход планирования Luna. Агент предложил минимальный вариант: один ход Luna, один `web.run`, один `alpha/search` в режиме live, текст страниц возвращается основной модели. Агент объяснил: `omp` — скомпилированный бинарник, расширение грузится в рантайме. Решили делать расширение. Агент сделал один файл `~/.omp/agent/extensions/codex-web-run.js`, 420 строк. Прогон на четырёх запросах прошёл.
**Основание:** Владелец попросил самый простой вариант с Luna на extra high и tier fast. Он принял цель и сказал, что ждал расширение. Сессия `01a1b487-dd8d`, реплики 131, 133. Ответы агента: 132, 134, 136.
**Причина:** Владелец хотел минимум кода и быструю, умную Luna. Расширение не требует пересборки OMP.
**Статус:** заменено 2026-11-08 в части «один круг»: цикл из нескольких кругов (реплика 141). Расширение, Luna, `xhigh`, `priority` и live остаются в силе.

## Действующие требования

1. Модуль — расширение OMP, а не правка провайдера.
2. Поиск — `web.run` Codex из MyPi вместо штатного `web_search` OMP.
3. Поиск идёт только в режиме live.
4. Поиск работает точно как в Codex CLI, кратчайшим путём. Принятые различия описаны в пунктах 6–12.
5. Кода как можно меньше, расширение декомпозировано.
6. Модель поиска — GPT-6 Luna (`gpt-6-luna`).
7. Luna работает с `xhigh` и `priority`. `priority` стоит только на ходе планирования Luna.
8. Поиск доступен любой основной модели OMP. Ищет всегда Luna и только при живом входе `openai-codex`.
9. Инструмент возвращает основной модели текст страниц. Ответ пишет основная модель.
10. Тот же `web.run` в `additional_tools` и тот же `alpha/search` с `external_web_access: true`, что в Codex CLI.
11. Выполняются только 4 команды: `search_query`, `open`, `click`, `find`.
12. В запрос поиска идёт только вопрос, без истории треда.
13. Один вызов инструмента даёт несколько кругов: поиск, чтение, уточнение.
14. Пределы цикла: 4 раунда, 8 вызовов `web.run`, 2 MiB входа, 180 с на запрос. При превышении цикл останавливается и отдаёт добытое.
15. Блоки результата помечены `[fetch N]`, раунды видны.
16. Расширение лежит целиком в одной папке, код отделён от схемы.
17. Пустой файл `disabled` в папке выключает расширение и возвращает штатный `web_search`.
18. Модуль — сырой снимок работы в рантайме, без правок, отдельный модуль репозитория.
19. Модуль остаётся в репозитории.
20. README описывает модуль по факту.
21. README минимален, без воды.
22. Файлы модуля ставятся в рантайм из репозитория через установочный контракт.

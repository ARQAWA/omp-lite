# История решений: voice-stt

Источник: переписки сессий OMP этого билда.
Действующие решения записаны в [DECISIONS.md](../DECISIONS.md).

## Хронология

### 2026-11-11 — Диктовка pi-voice-stt в пакете, и на VDI

**Решение:** плагин `pi-voice-stt` `v0.11.0` лежит копией в модуле и ставится с харнесом. На VDI `ffmpeg.exe` идёт в VSIX и запускается цепочкой PowerShell -> Git Bash. Ключ Soniox на VDI берётся из файла с именем-UUID в хранилище расширения.
**Основание:** задание владельца: «добавь в мой пакет OMP диктовку через плагин pi-voice-stt, она должна работать и на VDI», «зафиксируй версию плагина, не тяни main». Ответы в форме: копия в пакете; ffmpeg в VSIX, «чтобы он запускался абсолютно так же, как запускается OMP и сервер памяти»; имя микрофона пришлёт скрином; ключ «из файла в папке с расширением, имя UUID, что-то неприметное». Сессия `01a1c316-2c16`.
**Причина:** копия едет на Mac и VDI тем же путём, что весь харнес: без git и сети на VDI.
**Статус:** в силе. На VDI не проверено.
**Запись:** D-056

### 2026-11-11 — Диктовка проверена на Mac, ключ на VDI переделан

**Решение:** на Mac харнес переставлен, `PI_STT_CONFIG` прописан в `~/.zshrc`. Живая запись с микрофона дала текст в поле ввода. На VDI ключ читается из файла при каждой записи (ompcli 0.0.10).
**Основание:** владелец: «Ну поставь харнес. Пропиши конфиг», затем скрин с VDI `Missing Soniox API key` и слова «надо убедиться в том, что у нас диктовка работает на винде, на маке». Сессия `01a1c316-2c16`.
**Статус:** в силе. На VDI не проверено.
**Запись:** D-059

## Действующие требования

1. Диктовка работает на Mac и на VDI.
2. Версия плагина закреплена: `v0.11.0`.
3. Ключ не лежит в репозитории и конфигах.
4. ffmpeg на VDI запускается так же, как OMP и сервер памяти.
5. Клавиши не конфликтуют с OMP: `alt+w`, `alt+shift+s`.

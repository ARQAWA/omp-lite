# История решений: base-tools

Источник: переписки сессий OMP этого билда, с 2026-11-07. Предшественник: [cursor-tools.md](cursor-tools.md).
Действующие решения записаны в [DECISIONS.md](../DECISIONS.md).

## Хронология

### 2026-11-08 — Минимум кода и текста

**Решение:** каждая реализация минимальна по строкам и действиям. Описания тулов без воды.
**Основание:** слова владельца: «каждая реализация должна быть минимальное количество строк кода, минимальное количество действий»; «все описания должны быть максимально минималистичные, без воды, без мусора. Только по делу». Сессия `01a1b7e8-de03`, реплики 3 и 13.
**Причина:** общий принцип переноса. Действует и для тулов.
**Статус:** в силе
**Запись:** нет
**Коммиты:** нет

### 2026-11-08 — Тулы всегда видны, описания равны работе

**Решение:** базовые тулы видны агенту всегда, без подмены через `xd://`. Описания соответствуют реальной работе тулов.
**Основание:** слова владельца: «эти 6, они постоянно видны. У нас должно быть так же»; «соответствуют реальной работе наших инструментов». Сессия `01a1b8e9-2274`, реплики 4 и 6.
**Причина:** образец — тулы Cursor.
**Статус:** в силе
**Запись:** D-021
**Коммиты:** нет

### 2026-11-08 — Обёртки cursor-tools и схемы Cursor

**Решение:** поверх родных тулов стоят обёртки с теми же именами и описаниями Cursor. Позже владелец заказал смешанные обёртки, чтобы функционал не терялся.
**Основание:** слова владельца: «наше описание тулов, они полностью совпадают с описаниями тулов курсора» (сессия `01a1b8e9-2274`, реплики 3 и 7); «Делай смешанные обёртки, чтобы функционал не терялся.» (сессия `01a1bb5e-d176`, реплика 35).
**Причина:** паритет по workflow с Cursor.
**Статус:** заменено 2026-11-10: родные тулы и полная замена текста. Подробности в [cursor-tools.md](cursor-tools.md).
**Запись:** D-021, D-040
**Коммиты:** нет

### 2026-11-08 — Критерий успеха и установка через контракт

**Решение:** успех — живой вызов в OMP плюс тест модуля. Всё в репозитории ставится в рантайм через установочный контракт.
**Основание:** агент предложил критерий, владелец: «да, годится» (реплика 8). Затем: «всё ... должно ставиться через установочный контракт» (реплики 48 и 49). Сессия `01a1bb5e-d176`.
**Причина:** без установки модуль работал только по флагу `-e`.
**Статус:** в силе
**Запись:** D-024
**Коммиты:** нет

### 2026-11-09 — Минимум ходов агента

**Решение:** агент делает минимум своих ходов и максимум нужных независимых вызовов за ход. Файлы не читают и не ищут через `bash`.
**Основание:** слова владельца: «минимальное количество ходов», «чтобы он за один ход делал максимальное количество тул коллов». Сессия `01a1be27-9114`, реплики 16 и 17.
**Причина:** прежний текст разрешал лишние чтения ради пакета и раздувал число ходов (D-035).
**Статус:** в силе
**Запись:** D-034, D-035
**Коммиты:** 6d41ecd

### 2026-11-10 — Родные тулы, полная замена текста

**Решение:** самописные обёртки выброшены. Остаются родные `grep`, `glob`, `read`, `bash`, `edit`, `write` и свой тул `files`. Схемы родных тулов не меняются. Описания меняет хук запроса: текст родной заменён полностью. `bash` только для терминала. Из `grep` и `glob` вырезаны строки про Scribe. Правки многих файлов одним патчем.
**Основание:** слова владельца: «берём дефолтный функционал ... выбрасываем самописные ... схемы остаются те же самые, весь функционал остаётся тот же самый» (реплика 17); «полная замена родного текста ... в этом смысл ... заменяем родной текст», «независимые вызовы одним ответом», «Баш только для терминала ... мы это оставляем», «вырезаем из греб и глоб строки про Scribe, 100% вырезаем», «можно было ... по 30 файлов за раз» (реплика 24). Сессия `01a1c316-2c16`.
**Причина:** владелец потребовал взять дефолтный функционал и выбросить самописное. Смысл в том, чтобы заменить родной текст, а не дописать к нему.
**Статус:** в силе
**Запись:** D-040, D-041
**Коммиты:** 564e160, 45fddad

### 2026-11-10 — Карта и широкий поиск, не зависящие от git

**Решение:** тул `files` без `pattern` отдаёт карту папки целиком, с `pattern` ищет по содержимому тем же движком, что `grep`. Работает без git-репозитория, без потолка в 200 путей. `node_modules` и файлы из `.gitignore` не видны. Широкий поиск: до 20-30 ключевых слов, несколько грепов параллельно. Один патч на правку многих файлов.
**Основание:** слова владельца: «А если гита не будет ... эту проблему надо закрыть раз и навсегда» (реплики 26 и 27); «глубоко и жадно ... как можно больше файлов», «до 20, до 30 кейвордов» (реплика 27); «Node Modules не должен быть виден ... Файлы из git ignore ... должны ... пропадать» (реплика 28); «все правки одним патчем ... да» (реплика 29). Сессия `01a1c316-2c16`.
**Причина:** родной `glob` режет выдачу на 200 путей. Владелец требовал закрыть случай без git «раз и навсегда».
**Статус:** в силе
**Запись:** D-038, D-039
**Коммиты:** 0fb655b, 3b05e6e, b04f084, 0b2ebc0, fd91887, a83c7ba, 0b2ef9d

### 2026-11-10 — Порог 100 КБ, строка «файл целый», тул `files` на движке OMP

**Решение:** порог вывода 100 КБ. Ответ `read` называет целый файл строкой «файл целый». Имена `base-tools` и `files`. Тул `files` на движке OMP: агент назвал это обходом, владелец дал добро.
**Основание:** слова владельца: «порог ответа поднимает до 100 КБ ... строка файл целый, добро ... Имена Base Tools и Files подходят» (реплика 29); «Да, даю добро на ... файл, сделанный на движке OMP ... лучше на порядок берём» (реплика 30). Сессия `01a1c316-2c16`.
**Причина:** агент должен знать, дочитал ли он файл.
**Статус:** в силе
**Запись:** D-038, D-040, D-043
**Коммиты:** 4aa8410

### 2026-11-10 — Поиск: родной буквальный, размер через stat

**Основание:** слова владельца: «оставляем родной буквальный поиск. строгой проверки шаблона не добавляй» (сессия `01a1c6a6-0d84`, реплика 1); «бери размер сам через stat ... мок glob в тестах: без поля size ... тест на настоящем файле 5 МиБ ... мок повторяет форму живого ответа движка» (реплика 2).
**Причина:** родное поведение главнее нового валидатора.
**Статус:** в силе

### 2026-11-14 — Правка по файлам: несошедшийся файл пропускается

**Решение:** один вызов `edit` правит много файлов. Файл, который не сошёлся, пропускается, остальные пишутся. Ответ называет пропущенные файлы, причину и убранную секцию каждого файла. Пропуск идёт как ошибка. Без форка OMP: родной `edit` и два хука. Одинаково у главного агента, сабагентов и моделей GPT. Установлено в рантайм.
**Основание:** слова владельца: «множественное редактирование ... десятки, сотни файлов ... если хоть один файл не сошёлся, то мы продолжаем ... один файл ... не отредактировался, а все остальные отредактировались» (реплика 5); «самое простое, самое лёгкое, самое быстрое решение ... для всех моделей ... ничего не сломать ... Без форка ОМП», «да» (реплики 6 и 8); «так ... нельзя ... чтобы модель работала чётко ... и ничего не проёбывало», «Весь текст и код твой ... доведи до ... результата» (реплики 12 и 13); «Да» на «ставлю в рантайм?» (реплика 9). Сессия `01a1da1d-65f9`.
**Причина:** родной `apply_patch` при одном несошедшемся файле отвергал весь патч. Владелец не принял зелёный ответ, который скрывает пропуск.
**Статус:** в силе
**Запись:** D-076, D-080
**Коммиты:** b10fbfd, 2636ddb

## Действующие требования

1. Каждая реализация и каждое описание тулов минимальны: без воды, без мусора.
2. Родные `grep`, `glob`, `read`, `bash`, `edit`, `write` остаются с родными схемами и функционалом. Описания заменены полностью.
3. Базовые тулы видны агенту всегда. Описание соответствует реальной работе тула.
4. Агент делает минимум своих ходов и максимум нужных независимых вызовов за ход. `bash` только для терминала.
5. Из описаний `grep` и `glob` вырезаны строки про Scribe.
6. Тул `files` на движке OMP отдаёт карту папки и ищет по содержимому. Он не зависит от git и не режет выдачу на 200 путей. `node_modules` и файлы из `.gitignore` не видны.
7. Порог вывода 100 КБ. Строка «файл целый» в ответе `read`.
8. Плохая регулярка уходит родному движку, строгой проверки шаблона нет. Размер файла берётся через `stat`.
9. Сторож сверяет родные описания и настройки с эталоном и предупреждает владельца.
10. Порядок работы с файлами стоит один раз в `SYSTEM.md`.
11. На Windows и на Mac у `bash` нормальная родная строка.
12. Правка многих файлов одним патчем. Несошедшийся файл пропускается, остальные пишутся. Ответ называет пропуск как ошибку и сохраняет убранную секцию.
13. Всё ставится в рантайм по установочному контракту.

# История решений: memory-guide

Источник: переписки сессий OMP этого билда, с 2026-11-07. Предшественник: [memory-tool-prompts.md](memory-tool-prompts.md).
Действующие решения записаны в [DECISIONS.md](../DECISIONS.md).

## Хронология

### 2026-11-11 — Предупреждения о подмене описаний

**Решение:** причину предупреждений памяти надо найти и устранить.
**Основание:** слова владельца: «у меня опять какие-то ворнинги ебущие вылезают. Почему они вылезают, разберись.» Сессия `01a1c316-2c16`, реплика 64.
**Причина:** по ответу агента: тексты `recall`, `reflect` и `memory_edit` стали родными, наши тексты к ним не применялись.
**Статус:** в силе. Источник предупреждений убран решением следующей записи.
**Запись:** D-045
**Коммиты:** нет

### 2026-11-11 — Блок в системном промпте вместо подмены описаний

**Решение:** модуль `memory-tool-prompts` и его тесты удалены. Новый модуль `memory-guide` дописывает блок `<memory_use>` в системный промпт, пока память `mnemopi` включена. Выключена память: блок не вставляется. Описания тулов памяти остаются родными. Старые файлы удалены из рантайма.
**Основание:** слова владельца: «действительно ли нам нужно делать какие-то свои тексты для Reflect, Recall, Memory Edit? Или, может быть, нахуй их не надо? Может, просто мы напишем какой-то блок, который будет инжектиться в системный промт автоматически, с краткими инструкциями» (реплика 65); «я бы не стал их прямо в System MD пихать. Я бы сделал это как экстеншн ... если включено вот это вот память, мнемопай ... то он вставляется в System MD. А если выключен, то не вставляется.» (реплика 66); «Да, все 3 задачи.» (реплика 67, три задачи: память без сторожа, слепок настроек, обновление OMP); «Делая работу ... полностью доводи её до конца самостоятельно, код весь твой» (реплика 68). Сессия `01a1c316-2c16`.
**Причина:** по ответу агента: предупреждения уходят навсегда, код короче на 181 строку, обновление OMP эту часть не ломает. Три полезные строки сохраняются: не хранить секреты и токены, не хранить то, что есть в репозитории, не звать память на каждом ходу.
**Статус:** в силе
**Запись:** D-045
**Коммиты:** 4f39921, 2568f94

## Действующие требования

1. Своих текстов для `recall`, `reflect`, `memory_edit` нет. Описания тулов памяти родные.
2. Короткий блок с инструкциями по памяти встаёт в системный промпт автоматически.
3. Блок встаёт как расширение: память `mnemopi` включена, блок есть. Выключена, блока нет.
4. Сторожа эталона и предупреждений нет. Старые файлы подмены удалены из рантайма.
5. Работа доведена до конца без вопросов по деталям.

## Отменённое

1. Улучшение описаний тулов памяти, runtime-патч, точное совпадение с эталоном, визуальное предупреждение при сбое. Заменены 2026-11-11 блоком в промпте. Это требования из [memory-tool-prompts.md](memory-tool-prompts.md).
2. Предложение положить три строки в `SYSTEM.md`. Отклонено владельцем: блок идёт расширением (реплика 66).

### 2026-11-09 — Память Mnemopi на VDI без Ollama

**Решение:** память Mnemopi работает на VDI через локальную модель EmbeddingGemma внутри памяти omp-lite. Ollama не ставится. Работа памяти должна быть такой же, как на Mac. Агент нашёл путь: CPU-сервер llama.cpp (архив 24,9 МБ) и модель GGUF (около 310 МБ). Сервер запускается дочерним процессом расширения.
**Основание:** агент предложил портативную Ollama (реплика 14, 10:07). Владелец отклонил её и заказал модель внутри Mnemopi (реплика 15, 10:11). Агент ответил про 1,6 ГБ и предложил llama.cpp (реплика 20, 10:17). Он предупредил: на Mac модель идёт через MLX, на Windows предложен GGUF Q8, числа векторов могут отличаться, побайтовое совпадение обещать нельзя. Владелец отдельно на это не ответил. Сессия `01a1bf14-7a7b`.
**Причина:** архив Ollama тяжёлый из-за библиотек GPU. Для памяти они не нужны.
**Статус:** в силе
**Запись:** D-036

### 2026-11-09 — Выбор модели эмбеддингов

**Решение:** взять EmbeddingGemma 2 270M в форме Q8. Модель локальная, лёгкая, с русским и английским.
**Основание:** слова владельца: нужна лёгкая локальная модель для русского и английского без большого расхода оперативной памяти (реплика 21, 10:19). Агент сравнил два варианта: E5-small Q8 около 132 МБ с лимитом 512 токенов и EmbeddingGemma около 310 МБ для длинных записей. Он рекомендовал EmbeddingGemma (реплика 24, 10:22). Владелец согласился: экономия несущественна (реплика 25, 10:23). Агент подтвердил выбор (реплика 26). Сессия `01a1bf14-7a7b`.
**Причина:** при 32 ГБ оперативной памяти экономия 180 МБ мала. Длинные воспоминания удобнее.
**Статус:** в силе
**Запись:** D-036

### 2026-11-09 — Единый план из всего подготовленного

**Решение:** всё, что агент подготовил и спроектировал, собрано в один план. В плане три команды: `New Tab` запускает OMP, `New Terminal Tab` открывает обычный Git Bash, `Update` обновляет харнес при закреплённом OMP. Из PCLI взяты вкладки и обновление харнеса. Из CCLI взяты только части запуска. Автообновление OMP не переносится. Большие файлы скачивает само расширение: полный пакет может не пройти лимит Marketplace. План принят владельцем.

## Действующие требования

1. Модуль — расширение VS Code: OMP CLI для текущего omp-lite, чтобы владелец пользовался им на Windows VDI.
2. Расширение опубликовано в Marketplace VS Code. Владелец пользуется им так же, как PCLI.
3. Публикация идёт путём PCLI: агент публикует сам, на существующих токенах, без владельца.
4. Все правки только в репозитории omp-lite, публикация тоже. MyP, My OMP Harness и My Codex Harness только читаются.
5. Windows VDI проверяет владелец. Агент её там не запускает.
6. Память Mnemopi на VDI работает через локальную модель EmbeddingGemma внутри памяти omp-lite.
7. Память на VDI работает так же, как на Mac у владельца.
8. Ollama для памяти не ставится (архив около 1,6 ГБ).
9. Модель эмбеддингов локальная, лёгкая, скачиваемая, с русским и английским, без большого расхода оперативной памяти.
10. Выбрана EmbeddingGemma 2 270M в форме Q8: агент рекомендовал, владелец принял.
11. Есть команды вкладок `New Tab` и `New Terminal Tab` по образцу PCLI и CCLI. `New Tab` запускает OMP, `New Terminal Tab` открывает обычный Git Bash.
12. Команда `Update` обновляет харнес и сохраняет закреплённый OMP `18.18.0`. Автообновления самого OMP нет.

# review tests

После применения: `bun test dev/tests/harness/review`.
Вход теста: зарегистрированный инструмент `review`.
Модель и реестр OMP заменены тестовыми данными.
Проверяются изоляция входа, уровни, ошибки и отмена.
Цитаты WORKFLOW сверяются с исходным манифестом.

`cases.json` содержит синтетические приёмочные примеры.
Они не являются сообщениями настоящего владельца.
Для каждого передай `packet` инструменту `review`.
Проверь оба уровня: `blind` и `high`.
Сравни первый статус с `expected`.
У CLEAN обязательно конкретное CHECKED.
У FINDINGS нужны основания именно указанного дефекта.
BLOCKED должен назвать отсутствующий обязательный источник.

Один успешный набор не гарантирует будущие ответы.
Моки не доказывают понимание правил моделью.
Живая проверка исходящего запроса описана README модуля.
